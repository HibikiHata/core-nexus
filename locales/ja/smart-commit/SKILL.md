## ユーザー設定

以下の項目はプロジェクトに応じてカスタマイズできる。初回実行時、必要に応じてユーザーに確認する。

### 除外ファイル（git addしない）

- `.env`

### 差分確認の例外（パスのみでグループ判断）

なし（デフォルト）

<!-- 例:
- `logs/**` — ログファイルは差分が大きいためパスのみで判断
- `docs/archives/**` — アーカイブは内容確認不要
-->

### コミット前チェック（未追跡・変更があれば自動ステージング）

なし（デフォルト）

### 追加ルール

- 設定変更（chore）とドキュメント更新（docs）は必ず別コミットにする。ただし、設定変更とその記録・資料更新が同一作業の場合はまとめてよい。

## 手順

### A. ステージング済みファイルがある場合

1. `git diff --cached --name-only` でステージング済みファイルを確認する
2. ステージング済みの内容でコミットする
3. コミット完了後、報告する（プッシュはしない）
4. **ここで終了。手順Bは実行しない。**

### B. ステージング済みファイルがない場合（デフォルト）

1. `git status` で変更・未追跡ファイルの一覧を取得する
2. 除外ファイルをリストから除く
3. コミット前チェック対象があれば `git add -f` でステージングに含める
4. 残ったファイルそれぞれの差分を確認する（`git diff` または内容を読む）
5. 内容の性質でグループ分けを判断する（下記の基準を参考に）
6. グループごとに `git add` → `git commit` を順番に実行する
7. コミット完了後、作成したコミットの一覧を報告する（プッシュはしない）

## グループ分けの基準

| prefix | 対象の例 |
|--------|----------|
| `feat` | 新しい機能、スクリプト、モジュールの追加 |
| `fix` | バグ修正 |
| `chore` | 設定ファイル、依存関係、ビルド設定の変更 |
| `docs` | ドキュメント、README、コメントの変更 |
| `refactor` | 既存コードの構造改善（動作変更なし） |
| `test` | テストの追加・修正 |

同じprefixでも **関連性が低い**変更は別コミットにする。
同一トピックに関するファイル群なら同一コミットでよい。

## コミットメッセージ形式

```
<prefix>: <英語で簡潔に内容を説明>

Co-Authored-By: Claude <モデル名> <noreply@anthropic.com>
```
